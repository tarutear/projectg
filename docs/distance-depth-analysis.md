# 마커 거리값이 카메라 거리에 따라 변하는 문제: 원인과 해결책

## 1. 한 줄 결론
지금 코드에서 카메라 거리(깊이) 변화를 보정하는 경로는 **"기준점 좌표 ON + 보정(Calibration) 미설정"** 하나뿐입니다. 기본 모드(좌표 OFF)와 보정을 설정한 모드는 **고정 스케일**로 나누기 때문에, 값이 카메라 거리에 정확히 반비례(1/Z)합니다. 오히려 보정을 하면 깊이 보정이 꺼집니다. 유일하게 깊이를 보정하는 경로에서도 마커 반지름 측정 편향과 기하 효과 때문에 수 %에서 최대 20% 정도의 드리프트가 남습니다.

## 2. 원인 (증상을 설명할 가능성이 높은 순)
핀홀 카메라에서 두 마커 사이의 픽셀 거리는 `f·D/Z`입니다. 여기서 f는 초점거리(픽셀 단위), D는 실제 간격, Z는 카메라 거리입니다. 아래 수치는 1280×720, 수평 FOV 70°, f≈914 px를 가정한 시뮬레이션 결과입니다. 값이 Z와 무관하려면 똑같이 1/Z로 줄어드는 스케일로 나눠야 하는데, 코드에서 그 역할을 하는 것은 **마커 반지름뿐**입니다.

**① 보정을 설정하면 고정 px/cm가 쓰여 깊이 보정이 꺼짐** (보정 ON, 좌표 ON/OFF 무관, 두 검출기 모두)
- 보정은 한 프레임에서 `pxDist / cm` 값 하나만 저장합니다(`CalibrationPanel.tsx:31-34`). 이 값이 있으면 `pairScale`이 반지름을 무시하고 그대로 반환합니다(`coordinateStore.ts:50`). 녹화(`useMarkerTracking.ts:87-89,134`), 오버레이(`CameraView.tsx:90-93`), 목록(`AngleGroupList.tsx:44-48`) 모두 같은 방식입니다.
- 그래서 결과는 `D·Z_cal/Z`가 됩니다. 30 cm 떨어진 쌍을 60 cm 거리에서 보정한 경우: 카메라 30 cm → 60.0 cm, 50 cm → 36.0 cm, 100 cm → 18.0 cm (+100%에서 −40%).
- 패널 문구("마커 반지름 추정값 대신 이 값이 사용됩니다", `CalibrationPanel.tsx:40-41`)를 보면 보정이 더 정확한 옵션처럼 보입니다. 그래서 **꼼꼼하게 보정한 사용자가 오히려 이 증상을 가장 크게 겪습니다**.
- 보정값은 새로고침하면 사라지고(persist 없음, `coordinateStore.ts:19`), 카메라를 바꿔도 초기화되지 않습니다.

**② 좌표 모드 OFF(기본값)에서는 픽셀값이 그대로 저장됨**
- 기본값이 `enabled: false`(`coordinateStore.ts:20`)이고, 이때 `pxDist`가 그대로 저장됩니다(`useMarkerTracking.ts:106,133-135`). 30 cm 쌍 기준: 914 px(30 cm) → 548 px(50 cm) → 274 px(100 cm).
- `setMmPerPx`를 호출하는 곳이 없어서 mm 변환 경로는 동작하지 않는 코드입니다(`angleStore.ts:32`).
- **보정 ON + 좌표 OFF**이면 화면 배지는 cm로 표시되지만(`CameraView.tsx:92`의 `calibratedPxPerCm || coordEnabled` 조건), 녹화·차트·CSV에는 px가 저장됩니다(`SessionControls.tsx:32`, `DistanceTimelineChart.tsx:30,38`). 두 값 모두 1/Z로 변합니다.

**③ 좌표 ON + 보정 없음: 반지름 측정 편향 δ** (yellow·sticker 모두)
- 반지름은 `sqrt(contourArea/π)`로 계산합니다(`detector.ts:66,134`). 측정 반지름 r = 실제 반지름 + δ인데, δ는 깊이와 상관없이 **고정된 픽셀 값**입니다. 그래서 표시값이 `D/(1+δ·Z/(f·R))`가 되고, 오차가 Z에 비례해 커집니다.
- δ는 두 가지가 합쳐진 값입니다.
  - contourArea 다각형 손실: 항상 약 −0.46 px
  - HSV 고정 임계값(`detector.ts:5-7`) 효과: 배경색에 따라 경계가 안쪽이나 바깥쪽으로 −1.7~+1.7 px 이동
- 실제 20 cm 간격, 카메라 Z 30→90 cm 시뮬레이션 결과:

| 배경 | 30 cm | 90 cm |
|---|---|---|
| 피부 | 19.87 | 19.75 |
| 회색 | 20.20 | 20.84 |
| 흰 벽 | 20.73 | 22.59 (흐리면 24.40) |
| 어두운 옷 (흐림) | 18.94 | 17.29 |

- **오차의 방향은 배경이 정합니다.** 흰 배경에서는 멀어질수록 값이 커지고, 어두운 배경에서는 작아집니다.
- 웹캠의 영상 처리(ISP)나 JPEG 압축에 따라 δ가 ±0.4 px 정도 더 바뀝니다. 해상도가 640×480으로 떨어지면 상대오차가 2배가 됩니다(`useCamera.ts:17-18`은 `ideal` 요청만 함).
- 고정초점 웹캠은 가까울수록 흐려지기 때문에 δ 자체도 Z에 따라 변합니다. 어두운 배경에서는 흐림만으로 −10%까지 나왔습니다.

**④ 기하 효과: 반지름을 완벽하게 재도 생김** (좌표 ON)
- 두 마커의 깊이가 다르고 화면 중심에서 벗어나 있으면, 평균 반지름(`coordinateStore.ts:51`)으로 나눈 값은 `2|X_A·Z_B − X_B·Z_A|/(Z_A+Z_B)`가 됩니다. 이 값은 평면 거리도 3D 거리도 아니고, 카메라가 움직이면 바뀝니다.
  - 예: A는 광축 위, B는 20 cm 옆·10 cm 뒤에 있을 때 Z 30→90 cm에서 17.40→19.89 cm(+14%). 실제 3D 거리는 22.36 cm입니다.
  - `useMarkerTracking.ts:131-132` 주석에 적힌 "깊이 보정" 설명은 사실과 다릅니다.
- 평평한 원판 마커가 기울면 면적으로 구한 반지름이 √cosθ만큼 줄어듭니다. 30° 기울면 −7%, 50°면 −20%입니다. 화면 중앙에서는 일정한 오차지만, 가장자리에서는 Z에 따라 6~17% 변합니다.
- yellow 검출기의 원형도 검사는 반지름을 면적에서 구하기 때문에 계산값이 항상 1이고, 실제로는 아무것도 걸러내지 않습니다(`detector.ts:69`).

**⑤ sticker 모드의 상수 오류**
- `MARKER_RADIUS_CM = 1.0`(`coordinateStore.ts:3`)을 6 mm 스티커(반지름 0.3 cm, `detector.ts:88`)에도 그대로 씁니다. 그래서 값이 항상 3.33배로 나옵니다.
- 여기에 반지름 4~11 px 수준의 작은 스티커에 δ≈−1~−1.8 px가 붙어서, 깊이에 따른 드리프트가 25 cm에서 +9%, 60 cm에서 +36%입니다. 실제 30 cm 쌍이 108.7~136 cm로 표시되고, 약 65 cm보다 멀면 검출되지 않습니다.

**⑥ 고스트 마커 (일시적)**
- 놓친 마커가 마지막 위치와 반지름을 그대로 유지한 채 최대 60프레임 동안 남아 있습니다. 15 fps 기준 4초이고, 이 기간에도 거리 계산에 쓰입니다(`remapper.ts:19,83-87`, `useMarkerTracking.ts:63,82`). 카메라가 움직이는 동안 30 cm가 22~38 cm로 측정됐습니다.
- yellow 마커는 측정 반지름이 8 px 미만이면 버려지므로(`detector.ts:9`), 약 107~114 cm보다 멀면 사라집니다.
- 마커 ID가 확정된 상태에서는 60프레임이 지나면 영구히 빠지고 새 ID도 생기지 않습니다(`remapper.ts:73`).

**기타 (영향이 작거나 증상과 직접 관련 없음)**
- 렌즈 왜곡: 30 cm에서 1~4%(왜곡 계수는 가정값), 100 cm 이상에서는 0.5% 미만.
- Kalman 필터 지연: 0.5 cm 이하의 일시적 현상으로, 원인이 아닙니다.
- 녹화 중에 좌표 모드를 토글하거나 첫 프레임에 마커가 없으면 px 값이 "cm" 라벨로 저장됩니다(`useMarkerTracking.ts:98,104`).

## 3. 지금 어떤 모드인지 판별하는 방법
| 화면 상태 | 해당 원인 | 카메라 거리를 2배로 하면 |
|---|---|---|
| 거리 배지가 `px` | ② 좌표 OFF | 값 ×0.50 |
| 배지 cm + "보정 적용 중" 배너 | ① 보정 모드 | ×0.50 (보정한 거리에서만 정확) |
| 배지는 cm인데 차트는 px | ①+② (보정 ON, 좌표 OFF) | 둘 다 ×0.50 |
| 좌표 ON 버튼에 px/cm 표시, 보정 배너 없음 | ③/④ 반지름 모드 | 약 0.85~1.2배, 멀수록 오차 증가 |
| sticker 모드에서 실제 값의 약 3.3배 | ⑤ | 거리에 따라 +9~36%까지 변함 |
| 값이 몇 초간 멈추거나 튐 | ⑥ 고스트 | — |

**확인 실험**
1. 자에 두 마커를 20 cm 간격으로 붙이고, 화면 중앙에서 정면을 향하게 둡니다.
2. 카메라 40 cm와 80 cm에서 각각 5초씩 녹화합니다.
3. 비율 v80/v40을 봅니다.
   - 약 0.50이면 고정 스케일(①/②)입니다.
   - 0.85~1.2라면 ③ 또는 ④입니다. 두 거리에서 r도 함께 기록해서 구분합니다. r·Z가 일정한데 값이 변하면 ④(기하), r이 `a/Z + b`(b≠0) 형태로 맞으면 ③(반지름 편향)입니다.

## 4. 해결책

### 즉시 적용 (설정 변경 + 소규모 코드) — 권장 기본 경로
**설정만으로 지금 할 수 있는 것:** 좌표 모드를 **ON**으로 두고, 보정은 **"해제"**를 누르세요. 이것만으로 ①/②의 1/Z 오차(−40~+100%)가 ③ 수준(수 %)으로 줄어듭니다.

**코드 변경: 보정을 "px/cm 저장"에서 "유효 마커 반지름 R_eff 학습"으로 바꾸고, 마커별로 cm 변환**
- **`coordinateStore.ts`**
  - `calibratedPxPerCm`을 `markerRadiusCm`(R_eff)로 교체합니다. 기본값은 검출기별로 yellow 1.0, sticker 0.3입니다.
  - 거리는 항상 반지름 기반으로 계산합니다.
- **`CalibrationPanel.tsx`**
  - 15~30프레임 동안 평균을 내고, `missingFrames > 0`인 마커는 제외합니다.
- **`useMarkerTracking.ts` / `CameraView.tsx` / `AngleGroupList.tsx`**
  - 같은 함수 하나로 거리를 계산합니다.
  - 마커 중 하나라도 `missingFrames > 0`이면 null을 기록합니다.
  - 거리 계산을 원점 토글과 분리하고, `isFirstFrame` 처리를 고칩니다.
- **`SessionControls.tsx` / `session.ts` / `csvExporter.ts`**
  - 녹화 중에는 토글과 보정을 잠급니다.
  - 세션에 단위, R_eff, 검출기 모드를 저장하고, CSV에 단위를 표기합니다.

```ts
// 마커별 cm 변환: 자기 반지름으로 자기 깊이를 보정 (cx, cy = 화면 중심, f는 상쇄됨)
const toCm = (m: {x:number; y:number; radius:number}, cx:number, cy:number, Reff:number, delta = 0) => {
  const k = Reff / (m.radius - delta)                 // 이 마커 깊이에서의 cm/px
  return { X: (m.x - cx) * k, Y: (m.y - cy) * k }
}
export const pairDistanceCm = (a, b, cx, cy, Reff, delta = 0) => {
  const A = toCm(a, cx, cy, Reff, delta), B = toCm(b, cx, cy, Reff, delta)
  return Math.hypot(A.X - B.X, A.Y - B.Y)
}
// 보정: N프레임 평균 → Reff = realCm / mean(pairDistanceCm(a, b, cx, cy, 1))
```

- **남는 오차:** ①, ②, ⑤, ⑥이 제거되고, ④ 중 깊이차·화면 밖 성분도 사라져 정확한 평면 거리 `D·cosφ`가 나옵니다.
  - ③은 보정한 거리에서 0입니다. 30~100 cm 범위에서는 시뮬레이션 기준 약 ±1~3%이고, 흰 벽에 흐림까지 있으면 최대 ±7%입니다.
  - 지금의 좌표 ON 모드와 비교하면 드리프트 크기는 같습니다. 대신 보정한 거리를 기준으로 오차가 0이 되도록 맞춰지고, 마커 실제 크기가 달라도 흡수합니다.
- **UX:** 보정 방식은 지금과 같고(1~2초 소요), 사용자가 할 일은 늘지 않습니다.

### 중간 (정밀도 향상)
**(a) 현장 2-거리 보정 (R_eff와 δ 동시 추정)**
- 같은 쌍을 가까이와 멀리에서 캡처해 회귀합니다. 카메라 거리는 몰라도 됩니다.

```ts
// samples: {dpx, rbar}[]  (rbar 범위가 1.5배 이상이어야 함)
const { slope, intercept } = linreg(samples.map(s => s.dpx), samples.map(s => s.rbar))
const Reff = slope * realCm, delta = intercept   // 이후 toCm(..., Reff, delta)
```

- 시뮬레이션에서 yellow −0.4~+1.2%, sticker −0.4~+0.3%였습니다. 단, 흐림이 일정하다는 가정입니다.
- **반드시 실제 측정할 장소·배경·조명에서 보정해야 합니다.** 흰 벽에서 구한 δ를 피부 배경에 적용하면 −3.5~−12%로 오히려 나빠졌습니다.

**(b) 편향 없는 반지름 측정** (`detector.ts`, contour를 찾은 뒤)
- 선형 RGB에서 "마커색−배경색" 축으로 투영한 soft area를 구합니다. 실제 환경에서 예상 잔차는 ±1~3%입니다.
- 기울어짐에는 `fitEllipse`의 장반경을 씁니다(`types.ts`에 선언 추가 필요).
- 반지름에 EMA나 median 필터를 겁니다.
- 픽셀 개수 방식만 단독으로 쓰는 것은 **피하세요**. 피부 배경에서 편향이 +0.13 px에서 +0.60 px로 커집니다.

**(c) 마커별 3D 역투영** (몸 위 마커처럼 깊이가 서로 다를 때)

```ts
const f = (W/2) / Math.tan(HFOV/2 * Math.PI/180)    // 1280 px, 70° → 약 914 px
const Z = f * Reff / (r - delta); const P = [(u-cx)*Z/f, (v-cy)*Z/f, Z]
```

- 깊이차가 있는 쌍에서 −0.3~+0.8%였고, f가 10% 틀려도 영향은 ±2% 정도입니다.
- 반지름 품질에 의존하므로 (a)나 (b)와 함께 써야 합니다.

### 근본 / 고정밀
**(d) 기준 막대 비율법**
- 길이를 아는 막대에 마커 2개를 붙여 측정 평면에 함께 둡니다.
- `D = D_ref · pxDist / pxDist_ref`로 계산합니다(같은 프레임, 고스트가 섞이면 null).
- 반지름 대신 마커 중심점만 쓰므로 δ의 영향이 없습니다. 시뮬레이션에서 표준편차 0.002~0.017 cm였습니다.
- 막대가 측정 대상과 다른 깊이에 있으면 오차가 약 ΔZ/Z입니다(40 cm에서 5 cm 차이면 +12.5%).
- **UX:** 마커가 2개 더 필요합니다.

**(e) ArUco/ChArUco + 카메라 보정**
- `calibrateCamera`, `undistortPoints`, `solvePnP`로 기울어짐과 렌즈 왜곡까지 처리하는 완전한 3D 측정입니다.
- 이 방법은 시뮬레이션하지 않았고, mm 수준 정확도를 기대할 수 있습니다.
- 운영 환경은 CDN opencv.js를 씁니다(`useVisionWorker.ts:44-48`). 이 빌드에 `ArucoDetector`와 `solvePnP`가 들어 있는지 먼저 확인해야 합니다.
- 작업량은 3~5일 정도이고, 인쇄한 태그와 1회 체커보드 보정이 필요합니다.

**권장:** 먼저 **즉시 단계(R_eff 보정 + 마커별 변환 + 고스트 제외 + 단위 일관성)**를 기본으로 적용하세요. 1~2%보다 더 정밀해야 하면 (a)+(b)를, 임상 수준의 정확도가 필요하면 (d)나 (e)로 넘어가는 순서를 권합니다.

## 5. 남는 한계와 측정할 때 지킬 점
- **마커 기울어짐:** 30°에서 −7%, 50°에서 −20%입니다. 마커가 카메라를 정면으로 보게 붙이고, 코드 쪽에서는 `fitEllipse` 장반경을 쓰면 줄어듭니다.
- **평면 밖 움직임:** 2D 값은 `D·cosφ`입니다. 측정할 분절이 센서와 평행이 되게 카메라를 두거나, 3D 방식(4-c, 4-e)을 쓰세요.
- **렌즈 왜곡:** 30 cm에서 1~4%입니다. 마커를 화면 중앙 근처에 두고 카메라 거리를 50 cm 이상으로 하세요. 가까이에서는 마커가 화면 가장자리에 잘리지 않게 합니다.
- **배경·조명·흐림:** δ의 크기와 방향이 여기서 정해집니다. 마커 주변은 중간 톤(피부나 회색)으로 하고, 조명은 고르게 확산되게 하세요. 측정 중에는 카메라를 고정합니다.
- **검출 거리:** yellow 마커는 측정 반지름 8 px 아래에서 사라집니다(1280×720에서 약 107 cm, 640×480에서 약 55 cm). 반지름 15 px 이상(약 60 cm 이내)을 유지하거나 마커를 더 크게 만드세요.
- **해상도:** 지금은 `ideal` 요청만 하므로 해상도가 떨어지면 오차가 2배가 됩니다. 정확한 해상도를 강제하고, 바뀌면 보정을 무효화하도록 하세요.
